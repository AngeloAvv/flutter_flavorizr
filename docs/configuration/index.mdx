The configuration is `flavorizr.yaml` (or `flavorizr.yml`) in the root of the project, or the
`flavorizr` section of `pubspec.yaml`. The keys are the same in both. The pages of this section hold
the keys of each platform; this one holds the rest.

```yaml title="flavorizr.yaml"
app:                      # defaults for every flavor
  android:
    flavorDimensions: "flavor-type"
badge: false              # a band with the name of the flavor on its icon
icon: "assets/icon.png"   # the icon the badges are drawn on
launchScreen: false       # an iOS launch screen made from the icon of each flavor

flavors:
  dev:
    app:
      name: "My App Dev"
    android:
      applicationId: "com.example.app.dev"
    ios:
      bundleId: "com.example.app.dev"
    macos:
      bundleId: "com.example.app.dev"
    linux:
      applicationId: "com.example.app.dev"
    windows: {}

ide: [vscode, idea]       # run configurations
recipes:                  # what runs
  default: all
```

A key that flavorizr does not know **fails the run**, wherever it is, instead of being ignored: a typo
is much more likely than a key that is meant to do nothing. The error says where the key is and, when
one is close, which one was meant:

```text
flavorizr.yaml:6:7: Unknown key `bundle_id` in `flavors.apple.ios`: did you mean `bundleId` instead of `bundle_id`?
```

A key that is missing says which map it is missing from. The commands that read the configuration
(`plan`, `apply`, `status` and `list`) exit with `65` and write nothing, and `doctor` reports it as a
failed check. A key that is not text, such as `42:`, is refused too.

## Root keys

| Key | Type | Default | Description |
| --- | --- | --- | --- |
| `flavors` | map | | **Required.** The flavors, by name. See [Flavors](#flavors). |
| `app` | map | | What every flavor starts from: [`app.android`](/configuration/android#appandroid), [`app.ios`](/configuration/ios#appios) and [`app.macos`](/configuration/macos#appmacos). |
| `badge` | bool | `false` | Turns on the [badge](/icons-and-badge) of every flavor, unless a flavor says otherwise. |
| `icon` | string | | The source icon of the badges (and of the iOS launch screens), when a flavor has no `icon` of its own. It makes no icons by itself. |
| `launchScreen` | bool | `false` | Turns on the iOS [launch screen](/configuration/ios#the-launch-screen) of every flavor, unless a flavor says otherwise. |
| `recipes` | map | | Named lists of processors and recipes. `default` is what runs when no target is given. See [Recipes](/recipes). |
| `ide` | list or string | | The IDEs to write run configurations for: `vscode` and `idea`. See [IDEs](/configuration/services#ides). |

`instructions` and `assetsUrl` of 2.x are errors: see [Migration](/migration).

## Flavors

`flavors` maps the **name** of each flavor to its configuration. The name is what `flutter run
--flavor` takes, and the Flutter code has an enum value for each.

`init` only accepts a name that:

- starts with a lowercase letter and has letters and digits;
- is not a word of Dart (`class`, `new`...), and is not another name in other case (`qa` and `qA`);
- is not one Gradle refuses: `main`, `debug`, `release`, `profile`, or a name that starts with `test` or
  `androidTest`.

Follow the same rules when you write the file by hand. A run also refuses, before it writes anything,
a name that cannot be part of the name of a generated file: an empty one, `.` or `..`, one with
whitespace, a control or non-ASCII character, or any of `"`, `\`, `;`, `*` and `/`. On Windows the name
is also the name of an icon file, which excludes the ones the system reserves (`CON`, `NUL`,
`COM1`...).

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `app` | map | yes | The app of the flavor: [`name`](#app) and `icon`. |
| `badge` | bool or map | | The badge of the flavor. See [Icons and badge](/icons-and-badge). |
| `launchScreen` | bool | what the root says | Whether the iOS flavor has a [launch screen](/configuration/ios#the-launch-screen) made from its icon. It wins over the root, and only applies to a flavor with an `ios` section. |
| `android` | map | | [Android](/configuration/android) configuration. A flavor with no `android` is not built for Android. |
| `ios` | map | | [iOS](/configuration/ios) configuration. |
| `macos` | map | | [macOS](/configuration/macos) configuration. |
| `linux` | map | | [Linux](/configuration/linux) configuration. |
| `windows` | map | | [Windows](/configuration/windows) configuration. Write `windows: {}` for a flavor with nothing to set. |

A platform is flavorized when at least one flavor has a section for it. When none has, the processors of
that platform are skipped, and the run says so (`Skipping "macos": no flavors are configured for macos.`).
A flavor that has no section for a platform is not built for it.

### `app`

| Key | Type | Required | Description |
| --- | --- | --- | --- |
| `name` | string | yes | The name of the app, as the user sees it: the Android label, `CFBundleDisplayName`, the title of the window. |
| `icon` | string | | The icon of the flavor for every platform. A platform can have its own `icon`. See [Icons and badge](/icons-and-badge). |

## Icons and the badge in short

A flavor with an `icon` gets an icon set of its own. A flavor with no `icon` and no badge gets nothing
generated and builds with the default icon of the project (or with the icon the project already has for it, that flavorizr did not make). A badge makes icons for the flavor even when it
has no `icon`, from the root `icon` or the `AppIcon` of the project. The root `icon` alone makes nothing.
Every case, per platform, is in [Icons and badge](/icons-and-badge#every-case).

`generateDummyAssets`, a key of the platforms of a flavor in 2.x, is deprecated and ignored: remove it.
It will be an error in 4.0.
