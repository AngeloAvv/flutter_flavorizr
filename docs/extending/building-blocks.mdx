The stable API is small on purpose: `Flavorizr`, `FlavorizrProcessor`, `FlavorizrContext`, `Resource` and
`ResourceKey`. A processor has to say who owns what it writes with `ctx.track`, and `Artifact`, which that
takes, is **not** in the stable library: even a processor that writes a file whole imports
`experimental.dart` (see [Custom processors](/extending/processors)), and so has to pin the version of
flutter_flavorizr. The other pieces below are what the processors of flavorizr use to
edit files that **belong to the user**, without disturbing them and without writing twice.

```dart
import 'package:flutter_flavorizr/experimental.dart';
```

## What a processor tracks

`Artifact` says who owns a file a processor produces, and it decides what a run may do to it. There is no
way to build an artifact without an owner, so a processor cannot track a file without saying who owns it.

```dart
ctx.track(const Artifact.managed('lib/flavors.g.dart'));
ctx.track(const Artifact.patched('android/app/src/main/AndroidManifest.xml'));
ctx.track(const Artifact.scaffold('lib/flavors.dart'));
ctx.track(const Artifact.local('.idea/runConfigurations/dev.xml'));
```

`Ownership` is the enum of the four classes (`managed`, `patched`, `scaffold`, `local`): see
[File ownership](/concepts#file-ownership). `Artifact` is `sealed`, so a `switch` over one is checked for
exhaustiveness.

## Marked regions

`RegionMarker` is the pair of lines flavorizr writes around a part of a text file it owns:

```cmake
# ----- BEGIN APPLICATION_ID (autogenerated by flutter_flavorizr) -----
# ----- END APPLICATION_ID (autogenerated by flutter_flavorizr) -----
```

```dart
const marker = RegionMarker('APPLICATION_ID', comment: '#');
```

The markers are the ones 2.x writes, so a project flavorized by 2.x is recognized and nothing is duplicated.
What is outside the regions is yours, and is written back byte for byte, whatever its line endings.

## Owned keys

`InfoPlistEditor` replaces the value of a few `<string>` entries of an `Info.plist` in place:
`CFBundleName`, `CFBundleDisplayName` and the launch storyboard. Indentation, comments, line endings and the
order of the other keys are left as they are, and a plist that is up to date is not written. Its
`iosOwnedContent` and `macosOwnedContent` are what the lock hashes, so that whatever else you edit in the file
is never drift.

`VsCodeLaunchEditor` reads and edits `.vscode/launch.json` the way VS Code does, as JSONC: with comments and
trailing commas, adding, replacing or removing only the entries that carry the name of a flavor (the comments
inside a replaced or removed entry go with it, the other comments stay). A file it cannot read
is an error (a `FormatException`) that the caller decides what to do with.

A processor says what it owns of a patched file with `ownedContent`, a map from the path of the file to a
function that reads the owned part out of the file:

```dart
@override
Map<String, String Function(String source)> get ownedContent => {
  'ios/Runner/Info.plist': InfoPlistEditor.iosOwnedContent,
};
```

## Owned objects of the Xcode project

`XcodeprojResource` is the [resource](/extending/resources) that opens `Runner.xcodeproj` once and saves it
once. `OwnedObjects` is what a processor creates the objects of the project with:

- an object gets a **deterministic UUID**, derived from what it is (`flavorizr/<platform>/<target>/<flavor>/<kind>`),
  so two runs from scratch write the same `project.pbxproj`;
- `ensure` finds the object by its UUID before it creates it, so a run is idempotent, also when the lock was
  lost;
- an object that already exists from Flutter, from you or from 2.x is reused as it is, and never re-keyed or
  removed, unless the processor knows it is flavorizr's and claims it;
- `settle` removes what the last run created and this one did not, and tells the context what the
  processor owns, which is recorded in `flavorizr.lock`.

```dart
// XCBuildConfiguration is a class of package:dart_xcodeproj.
final owned = OwnedObjects.ios(ctx);

for (final flavor in ctx.desiredFlavors.keys) {
  owned.ensure<XCBuildConfiguration>(
    (graph, uuid) => XCBuildConfiguration(graph, uuid),
    flavor: flavor,
    kind: ['buildConfiguration', 'Debug'],
    existing: () => configurations['Debug-$flavor'],
    create: (config) {
      config.name = 'Debug-$flavor';
      list.buildConfigurations.add(config);
    },
  );
}

owned.settle();
ctx.track(XcodeprojResource.iosArtifact);
```

The model of the objects is the one of [dart_xcodeproj](https://pub.dev/packages/dart_xcodeproj). The
format of what the lock records is in [`flavorizr.lock`](/reference/lock#owned-objects).

## The configuration

The models of the configuration are exported too: `FlavorizrConfig`, `Flavor`, `App`, `Android`, `Darwin`,
`Linux`, `Windows`, `FlavorBadge` and the others. A processor reads them through `ctx.config`, and they are
**read-only**: the maps and the lists are unmodifiable.

```dart
for (final MapEntry(key: name, value: flavor) in ctx.config.flavors.entries) {
  final label = flavor.app.name;
  final applicationId = flavor.android?.applicationId;
}
```

`ctx.config.badgeOf(name)` is the resolved [badge](/icons-and-badge) of a flavor, and `ctx.config.iosFlavors`
(`androidFlavors`, `macosFlavors`...) the flavors built for a platform.

## The badge

`BadgeColor`, `badgePalette`, `defaultBadgeColor`, `ResolvedBadge` and `resolveBadgeSourceIcon` are the
pieces of the [icon badge](/icons-and-badge#icon-badge): the palette, the color a flavor gets by default
and the source icon a badge is drawn on.
